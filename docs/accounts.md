# ログインとアカウント管理

ログインID（社員番号）とパスワードで利用します。社員番号は先頭の0を保持します。保存・計算・削除・研究・パッケージ読込の操作履歴にはログイン中のIDを自動記録し、画面で別の社員番号へ変更できません。

## 初期管理者の登録

新しいDocker環境では、起動後にサーバーのコンソールで初期管理者を1回登録します。固定の初期パスワードや、ブラウザからの自由な管理者登録はありません。

```bash
docker compose up --build -d
docker compose exec api python -m app.accounts create-admin --username admin
```

表示されるプロンプトで12〜128文字のパスワードを2回入力し、ブラウザでログインしてください。入力したパスワードはコンソールに表示しません。`--temporary` を追加すると、初回ログインでパスワード変更を必須にできます。管理クラウド環境でのCompose追加ファイルはREADMEの起動手順を参照してください。

## アカウントの発行と管理

管理者だけに「アカウント管理」を表示します。

1. ログインIDと表示名を入力し、「アカウントを発行」を押します。通常は一般ユーザーとして発行します。「管理者として発行」を選ぶと、全モデル・アカウントを管理できるユーザーになります。
2. ランダムな仮パスワードをその画面で1回表示します。本人へ伝え、初回ログイン時に変更してもらってください。画面を閉じた後は取得できません。
3. 一覧はログインID・表示名で検索でき、25件ずつ表示します。「編集」から表示名、管理者権限、有効状態を変更できます。
4. パスワードを忘れた場合は「仮パスワードを再発行」で新しい仮パスワードを発行します。古いパスワードとログインを無効にし、次のログインで変更を求めます。
5. 利用を休止する場合は有効状態を外します。戻すと再度ログインできます。アカウントの削除は論理削除で、ログインを無効にし、モデル・計算履歴・操作記録を残します。削除したログインIDは再使用できません。

権限・有効状態の変更、削除、仮パスワード再発行で、そのユーザーの既存ログインを解除します。自分自身のアカウント削除・無効化・管理者権限解除は禁止します。同時に複数の管理者が操作しても、有効な管理者を失わないようDB側で直列化します。

右上の鍵アイコンから自分のパスワードを変更できます。変更後はその画面のログインを更新し、他のログインを解除します。編集中の内容は保持します。ログアウトすると画面内のモデル・結果を閉じます。

## モデルの所有者と閲覧範囲

| 対象 | 一般ユーザー | 管理者 |
| --- | --- | --- |
| モデル一覧・検索・件数 | 自分の所有モデルのみ | 全モデル |
| モデルの閲覧・編集・削除・計算 | 自分の所有モデルのみ | 全モデル |
| 計算・研究履歴、停止・再開、CSV、比較、パッケージ | 関連モデルの所有者に従う | 全モデル |
| 自分が登録した参照データ | 閲覧・比較可能 | 全参照データ |
| アカウント発行・管理、モデル所有者の変更 | 操作不可 | 操作可能 |

新規保存とパッケージ読込では、ログイン中のアカウントを所有者にします。管理者が他の人のモデルを編集しても所有者は変わりません。他人のIDを指定したAPIアクセスも拒否します。

認証追加前に保存したモデルは、保存時の社員番号から所有者を自動推定せず、**未割当として管理者だけが閲覧**します。既存の回路・版・結果を保持するDB移行は起動時に行います。

管理者は「保存済みモデル」で対象を選択し、「新しい所有者」から有効なアカウントを選んで割り当てられます。複数モデルもまとめて変更できます。「管理者のみ（未割当）」に戻すこともできます。変更時は版を更新し、対象の更新競合があれば全件の変更を中止します。

所有者を変更すると、そのモデルにひもづく過去の計算・研究履歴のアクセス権も移ります。計算時の入力・数値・表示名は変更しません。アカウントを削除した人のモデルも、この操作で別の人に引き継げます。

## サーバー設定・復旧

パスワードはPBKDF2-SHA256（60万回、ランダムsalt）でハッシュ化して保存します。ログインはランダムなセッションCookieを用い、DBにはそのハッシュのみを保存します。CookieはHttpOnly・SameSite=Strictで、変更操作はセッションごとのCSRFトークンも検証します。APIデータは `Cache-Control: no-store` で返します。

通常のログイン有効期間は8時間です。`.env` の `SESSION_TTL_SECONDS` で15分〜24時間に設定できます。ログイン試行には15分単位の制限があります。ログインIDごと8回の失敗、APIが見える接続元ごと100回の試行で一時停止します。

HTTPSのリバースプロキシから利用する場合は、`.env` で次の設定を行い、API・workerを再作成します。`CORS_ORIGINS` はブラウザが使う正確なURLを指定します。

```dotenv
AUTH_COOKIE_SECURE=true
CORS_ORIGINS=https://plasma.example.jp
```

ローカルの `http://localhost:8080` では `AUTH_COOKIE_SECURE=false` を使います。パスワードをURLやコマンド引数に渡さず、管理画面またはコンソールの入力を使ってください。

管理者のパスワードを忘れた場合はサーバーのコンソールから復旧できます。

```bash
docker compose exec api python -m app.accounts reset-password --username admin --temporary
```

この操作は既存ログインを解除します。削除済みアカウントの復元や権限の自動昇格は行いません。別の管理者が必要なら `create-admin --username 別のID` で明示的に作成してください。

自動検証用には `--password-stdin` も使用できます。検証アカウントは専用のDBで発行し、テスト後にそのDBを破棄します。パスワードやCookieを検証レポート・Gitへ保存しません。[認証の受入スクリプト](../scripts/check_accounts.py)は専用インスタンスを対象に、発行・ログイン・権限・実計算・所有者変更を確認します。

検証用Composeは別プロジェクトのDB・Redisを使い、ブラウザをローカルの8081へ公開します。先に通常のイメージをビルドしてください。

```bash
docker compose -p plasma-auth-check -f compose.yaml -f compose.test.yaml up --no-build -d
docker compose -p plasma-auth-check -f compose.yaml -f compose.test.yaml exec api python -m app.accounts create-admin --username qa-admin --temporary
```

入力した検証用仮パスワードを、`.private/auth-test-admin.json` に `username` と `password` のJSONとして用意します。受入スクリプトは初回変更後のパスワードをこのファイルへ更新します。使い捨てDBであることを確認して実行し、完了後はDBを破棄してください。

```bash
python scripts/check_accounts.py --base-url http://localhost:8081 --admin-file .private/auth-test-admin.json --confirm-isolated-test-db
docker compose -p plasma-auth-check -f compose.yaml -f compose.test.yaml down -v
```
