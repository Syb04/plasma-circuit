# 過渡解析の時間単位切替の確認

2026-10-08、Docker上の実UI/APIとngspiceで確認した。時間入力は **ps・ns・µs・ms・s** に対応する。

| 入力 | 初期表示単位 | 保存する設定キー（秒） |
| --- | --- | --- |
| 通常過渡解析：出力時間刻み | µs | `time_step` |
| 通常過渡解析：終了時間 | ms | `stop_time` |
| 時間発展0D：終了時間 | ms | `stop_time_s` |
| 時間発展0D：RF再評価間隔 | µs | `rf_update_interval_s` |

表示単位を切り替えるだけでは計算条件を変更しない。既存の秒値を読み込み、未指定のRF再評価間隔も維持する。表示単位の選択はUI内の状態で、計算履歴には秒値を記録する。

## 確認結果

- TypeScript/ViteとDockerフロントエンドのビルドに成功。
- 実ブラウザで6項目を確認し、実行時エラーは0件。
- 5単位への換算、入力編集、空欄からの復帰、詳細JSONによる更新を確認。
- 非線形電荷EDDを25 ns刻み・終了時間2 µsで実計算し、`succeeded` / `converged=true`。API送信値とDBから読み出した実行条件が一致し、保存回路の再読込でも物理時間を維持。
- 時間発展0Dの終了時間とRF再評価間隔、指定電力モードへの切替を確認。マクロソルバーの再検証は今回の対象に含めていない。
- 幅390 pxで時間入力の横はみ出しがなく、ライト／ダークの表示とキーボードフォーカスを確認。

実行ID・秒値・対象ソースのSHA-256は [verification.json](verification.json) に記録した。画面は [通常過渡解析](transient-desktop.png)、[時間発展0D](macro-desktop.png)、[モバイル](macro-mobile.png)、[モバイル・ダーク](macro-mobile-dark.png) を参照。
