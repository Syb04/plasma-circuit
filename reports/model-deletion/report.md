# 保存済みモデルの選択・削除

2026-10-08、Docker上のReact UI・PostgreSQL・Redis/RQ・実ngspiceで検証した。

モデル一覧のチェックボックスで1件または複数件を選び、名前・版・削除者の社員番号を確認して削除できる。「このページをすべて選択」は表示中のページだけが対象で、検索・絞り込み・並べ替え・ページ送り・一覧更新で選択を解除する。最終ページの最後のモデルを削除したときは、先頭ページへ戻る。

削除は1〜100件を一つのトランザクションで実行する。他の人が対象の版を更新した場合、または既に削除した場合は409を返して全件を中止し、UIで一覧を更新して再選択を促す。PostgreSQLではID順に行ロックを取得し、重なる一括削除も直列化する。削除時刻・社員番号をDBへ記録する。

モデルは一覧から消え、再読込・上書き・新しい計算／研究の作成ができなくなる。過去の版・runの入力と結果・研究ケースと再試行履歴・参照・パッケージの来歴は保持する。既に投入した計算は続行でき、既存研究の失敗ケースも保存した入力から再試行できる。履歴を残す論理削除で、復元・物理削除APIは設けていない。

編集中のモデルを削除した場合、手元の回路・未保存の名前とメモ・計算条件・履歴は保持する。次の保存は新しいモデルIDを作成し、削除済みのモデルを復活させない。

パッケージの書き出し日時と封筒ハッシュは各エクスポートで変わるため、入力・結果・モデルと内容ハッシュを比較した。計算条件の時間単位は編集パネル再表示時に既定のµs表示になるが、SIで保持した37 ns = 0.037 µsは変わらない。

API／ワークフロー試験は隔離SQLiteと模擬キューを使い、削除後の投入済みジョブの完了・研究再試行も確認する。ブラウザ試験の過渡計算は実Redis/RQとngspiceを使う。検証用モデルだけを削除し、既存モデル60件は一覧にも保持した。全8テーブルの既存レコードについて、ブラウザ検証後も更新前と同じ行内容で、既存モデルの削除記録が0件であることを照合した。

再実行方法：

```bash
docker compose run --rm --no-deps api python -m pytest tests/test_model_deletion.py tests/test_api.py tests/test_workflows.py -q
python scripts/check_model_deletion.py --base-url http://localhost:8080
```

ブラウザ検証は自身のモデル26件、編集中の内容を保存したコピー1件、同時削除用3件、実計算1件を作成する。正常終了時に自身のモデル30件をすべて論理削除し、計算履歴は保持する。途中で失敗した場合は `verification.json` の対象ID・社員番号に照合して検証用モデルを整理する。
